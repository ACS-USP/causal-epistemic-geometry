# Paper 1 figure plan

The main-text package should use five figures. Six figures would over-weight
the developmental atlas relative to the confirmatory result; layer/readout
material belongs in the appendix unless the manuscript's venue strongly favors
mechanistic breadth.

All implemented data figures are generated by
[`scripts/generate_paper1_figures.py`](../scripts/generate_paper1_figures.py)
from tracked canonical JSON. The script records source and output SHA-256
digests in `manuscript/figures/paper1/SOURCE_MANIFEST.json`. No value is typed
into plotting code when a machine-readable artifact exists.

## Figure 1 — From intervention to error-profile complementarity

**Purpose:** define the causal object before presenting metrics.

Flow:

```text
source contrast -> internal direction -> frozen intervention
    -> model variant -> item error propensities
    -> overlap / G / C / D / rescue / damage
```

Show repeated baseline sampling and matched random directions as distinct
counterfactual controls. Keep the figure conceptual; it should not imply that
representation distance predicts error distance.

Artifact: `figure1_conceptual_framework.{svg,png}`.

## Figure 2 — Qwen development to confirmation

**Purpose:** show that controller choice preceded the final test and that the
effect exceeds finite random banks in both stages.

- Left: meaningful C and individual random C values for Gate 9 DEVELOPMENT and
  Q1 CONFIRMATORY.
- Right: rescue versus damage for the meaningful controller in both stages.
- Mark stages visibly rather than pooling them.
- Caption the distinct N and do not use development uncertainty as
  confirmatory evidence.

Artifact: `figure2_qwen_development_confirmation.{svg,png}`.

## Figure 3 — Ministral complementarity and safety dissociation

**Purpose:** prevent the terminal fail from erasing supported dimensions.

- Left: Gate 13.1 DEVELOPMENT and Q1 CONFIRMATORY meaningful C against each
  stage's random bank.
- Right: rescue/damage. The confirmatory commitment-validity result is shown
  directly in Figure 4 to avoid mixing outcome scales in one panel.
- The title/caption must say “complementarity reproduces; safety guard fails,”
  not “partial pass.”

Artifact: `figure3_ministral_development_confirmation.{svg,png}`.

## Figure 4 — Confirmatory evidence vector, not one Boolean

**Purpose:** make the conjunction visible.

For Qwen and Ministral, place side by side:

- C and accuracy change;
- baseline and meaningful commitment validity;
- each model's frozen relative/absolute validity floor.

Annotate the exact terminal model decisions. This is the paper's visual version
of `f(E) != E`.

Artifact: `figure4_complementarity_safety_dissociation.{svg,png}`.

## Figure 5 — Domain boundary of the fixed Qwen controller

**Purpose:** show the strongest generalization result, including the negative.

Compare Gate 9 CRUXEval and Gate 10 long character count for:

- accuracy change;
- C;
- D;
- meaningful value versus the corresponding random mean.

The controller, model, layer, dose, and timing are fixed across domains. This
supports a domain-conditioned interpretation and is more informative than an
additional success-only panel.

Artifact: `figure5_cross_domain_boundary.{svg,png}`.

## Appendix candidates

### A. Readout versus causal layer ranking

Gate 13 source eligibility spans all 34 layers, while causal qualification
selects a narrower layer-dose set. A fair appendix figure requires a
pre-declared mapping between source-score fields and causal-stage fields. The
artifacts exist, but mixing shortlist, all-layer sweep, and disjoint dose-stage
samples in one main figure risks implying a single comparable outcome. Document
this as a gap rather than hand-combine heterogeneous stages.

### B. Post-hoc Ministral invalidity taxonomy

An aggregate stacked bar can be generated from
`manuscript/data/posthoc_ministral_invalidity_aggregate.json`. It belongs in an
appendix because the taxonomy is post-hoc and same-analyst, and because raw
examples cannot be exported on the remote-safe branch.

### C. Development ladder

A timeline of null, destructive, calibration, replication, and confirmation
could help readers audit selection, but it is better as a compact methods table
unless space permits.

## Visual and statistical rules

- Never pool DEVELOPMENT and CONFIRMATORY rows.
- Show all four random values, not only their mean or maximum.
- Use item-bootstrap intervals only where the canonical artifact contains them.
- Keep mechanical validity separate from correctness.
- Do not hide negative C/D values or truncate axes to suppress them.
- Do not use post-hoc recovered answers in any plotted outcome.
- Every caption names model, task, stage, N, and status.
